# macOS 原生窗口验收

Refs #333。日期：2026-10-17。

## 环境与方法

- Apple M1 Pro，macOS 27.0.1，内建 Liquid Retina XDR 面板 3024×1964。
- 原始系统显示模式 1512×982；五档模式下 WebView `devicePixelRatio` 均为 2。
- 从当前工作目录构建调试应用，核对 bundle ID `com.fileterm.desktop.dev`、名称 `FileTerm Dev` 和 bundle 内运行进程。通过原生 UI 操作系统显示设置和应用；未使用浏览器视口模拟替代桌面窗口。
- 原生 Web Inspector 读取实际 viewport、DPR 和 screen 工作区；原生截图检查工具栏、底栏及表单滚动。窗口尺寸单位为逻辑像素。
- 应用内界面缩放为 100%，记住窗口尺寸关闭。仅打开临时 Shell 文件与空白新建连接表单，未保存连接或连接远端。

## 主窗口运行中切换系统显示模式

| 系统显示模式     | 可用工作区 | 实际内容区                   | 结果                     |
| ---------------- | ---------- | ---------------------------- | ------------------------ |
| 1024×665         | 1024×601   | 1000×553                     | 无横向溢出，底栏在窗口内 |
| 1147×745         | 1147×679   | 1123×631（原生截图尺寸换算） | 窗口完整，底栏可见       |
| 1352×878         | 1352×806   | 1150×758                     | 无横向溢出，底栏在窗口内 |
| 1512×982（默认） | 1512×906   | 1280×820                     | 无横向溢出，底栏在窗口内 |
| 1800×1169        | 1800×1087  | 1150×790                     | 无横向溢出，底栏在窗口内 |

这些尺寸来自连续切换期间的实际状态，不代表每次启动都采用表中相同大小。系统会参与调整、恢复原生窗口尺寸。

## 发现与修复

初版在默认模式运行后切换 1024×665，主窗口仍受旧的 1150×790 最小尺寸限制，右侧和底部越出屏幕；小屏下重启则能适配。

现在主窗口和独立窗口复用显示工作区变化监听。在移动、尺寸、DPI 或获得焦点事件中，只有显示工作区或缩放因子变化才重新适配；普通拖动和调整大小不重设窗口。macOS 显示模式可能改变工作区而保持 DPR 为 2，因此不能仅监听 DPI 事件。最大化或全屏时保留系统尺寸管理。

修复后的开发 bundle 已重建并完成上述五档切换。

## 独立窗口和小窗口

- 默认模式：编辑器 1220×780，连接表单 860×680；工具栏和状态栏、取消/测试/保存按钮可见。
- 1024×665 下新建：编辑器 1000×553、连接表单 860×553；编辑器查找弹层可见，表单末尾认证字段可滚动到达，固定按钮未被挤出。
- 默认模式先打开编辑器，再切换 1024×665：实际内容区 1000×548，DPR 2，无横向溢出，状态栏底部 534，小于内容区高度。文件名、保存/关闭、LF、编码与语言状态完整。
- 默认模式先打开连接表单，再切换 1024×665：窗口完整，固定底部按钮可见；在表单区域滚动后末尾 sudo/su 字段可见，未与按钮重叠。
- 测试结束恢复 1512×982，确认系统设置选中默认模式；关闭测试窗口及 Inspector 并退出测试 bundle。应用偏好与窗口状态文件和备份一致。

## 未覆盖

- Windows、Linux X11/Wayland：本机没有原生环境，未做 UI 实测。
- 外接 1080p/2K/4K/5K 显示器、1× 屏幕、混合 DPI 跨屏拖动、不同 Dock 布局未实测。
- 未覆盖所有页面、应用内缩放档位、最大化/全屏切换、记住大窗口后换屏重启；未通过拖动验证每种最小窗口尺寸。
- 自动几何矩阵覆盖不能替代这些原生平台验收，见 [显示矩阵](window-display-matrix.md)。
