# 串口实现审查

审查日期：2026-10-14；补齐日期：2026-10-15。三项实现问题已补齐，实体串口验收另行记录。

## 已有能力

FileTerm 已覆盖基本参数、端口枚举和手动路径、UTF-8/GBK 等流式解码、写入/flush 超时与
取消。还提供 Text/Hex、换行转换、本地回显、逐字节/逐行发送延迟、USB 身份匹配重连、
DTR/RTS/Break、线路状态、RS-485、mark/space parity、Raw/X/Y/ZMODEM/Kermit、宏和循环
发送，以及串口原始字节日志。

## 本次补齐

| 问题                           | 实现与验证                                                                                                                                                                                                                       |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 普通发送等待期间暂停接收       | `serial/duplex.rs` 在写入和 flush 等待期间继续读取。复用当前流式解码器、接收日志和终端输出；保留现有有界命令队列，文件传输仍独占协议流。测试覆盖发送阻塞时接收、取消以及发送期间 EOF。                                           |
| 设备打开缺少超时和迟到句柄回收 | 连接和测试连接共用 `serial/open.rs`，在 blocking worker 中打开端口并限制等待为 15 秒。正常连接响应取消；迟到结果由自身清理配置的关闭线路状态并释放句柄。测试模拟超时、取消和迟到返回，确认只回收一次；预先取消的调用不访问设备。 |
| 连接列表缺少串口参数摘要       | 连接管理器、首页近期和全部连接卡片共用 `connection-profile-summary.ts`，显示设备、波特率和帧格式，搜索包含摘要。测试覆盖五种 parity 的 `N/O/E/M/S` 标签和旧字段默认值。网络连接沿用原有摘要。                                    |

## 验收边界

- 原生驱动调用开始后不能被 async 超时强行终止；迟到句柄在驱动调用返回后释放。
- Windows/macOS 的设备打开、占用、拔插、DTR/RTS、Break、RS-485 换向及真实 CTS 阻塞
  仍需实体设备验证。自动化中的发送阻塞是内存流模拟，不代表实体流控已验收。
- Linux PTY 验证基本打开和异步收发；它不能代替真实线路和协议互操作验收。
- 本机类型、lint、renderer（69 项）、Rust/contract（767 项）、Clippy 和 CSS contract
  已通过。本次源码和文档格式检查通过。
