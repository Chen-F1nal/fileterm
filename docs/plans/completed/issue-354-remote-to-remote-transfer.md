# Issue #354：密钥同步核查与服务器间文件传输

状态：实现与本机验收已完成；原生三平台与真实远端矩阵仍待验证。核查日期：2026-10-25。

关联：[Issue #354](https://github.com/St0ff3l/fileterm/issues/354)。本文不代表发布验收完成，不关闭 Issue。

## 现状与结论

Issue 包含两个独立需求：不同服务器之间传文件，以及 Windows 便携版 WebDAV 同步缺失 SSH 密钥。

- 反馈者确认使用正式版 2.2.31。该版本 `webdav/bundle.rs` 的导出只调用 `encrypt_profiles`，不导出 SSH 密钥库。
- 评论日志显示上传完成、下载 `imported=4 updated=0 skipped=0`；这些是配置导入数量，不能证明导入了私钥。Tao 的 DEBUG 事件循环日志没有提供密钥同步失败证据。
- 提交 `28c8f6af`（2026-10-16），经 [PR #322](https://github.com/St0ff3l/fileterm/pull/322) 合入，增加 WebDAV/S3 的密钥打包与恢复。该提交已包含于 `origin/main` 和 `v2.3.1`。
- [正式版 2.3.1](https://github.com/St0ff3l/fileterm/releases/tag/v2.3.1) 于 2026-10-24 发布。其发布说明明确包含 SSH 私钥和已保存口令的加密备份。
- 当前 `webdav/bundle.rs` 导出 FileTerm 密钥库，下载先验证并恢复密钥，再导入配置；`ssh_keys/backup.rs` 在目标设备重新加密口令，保留本机独有密钥，同 ID 不同密钥拒绝同步。备份不会读取任意外部 `privateKeyPath` 文件。
- 因此，密钥同步已在代码和发布层面覆盖，但尚不能声称该用户环境已验证解决。两端升级到 2.3.1 或更新版本后，必须由持有私钥的源端重新上传，再在目标端下载；旧云端备份不会自动获得私钥。外部私钥应先导入 FileTerm 密钥库。
- 跨服务器传输尚未实现：共享 `TransferTask.direction` 只有 upload/download，任务只有一组连接身份；`app_copy_remote_path` 也只向一个 tab 的 worker 发送操作，属于同会话复制。

## 首版范围

支持用户主动把文件或目录从服务器 A 复制到服务器 B，覆盖 SFTP、FTP、显式/隐式 FTPS 之间的组合。首版只支持普通用户文件通道，隐藏或禁用 root 来源/目标并说明原因。

首版不做双向同步、镜像删除、定时任务、跨服务器剪切、FXP，以及远端执行 scp/rsync。目录复制不承诺整棵目录原子提交；已完成文件保留，失败文件可恢复，目标额外文件不删除。

## 用户操作

调研 Termius、Xftp、WinSCP、MobaXterm 和 SecureFX 后，采用独立全高“文件传输”标签页；原有终端文件面板保留。

1. 当前文件工具栏提供入口；根据用户调整，窗口顶部不再放重复的文件传输快捷按钮。首次打开复用系统信息的标签插入方法，紧跟当前标签右侧；重复打开复用原标签及位置。第一次从文件区打开时，左侧带入当前服务器与目录；右侧默认本地，可以选择另一个已连接的服务器。
2. 两侧独立浏览目录、输入路径、筛选和多选，支持拖拽、左右复制按钮和右键复制；不改变原会话的工作目录。
3. 同名默认跳过，也可选择覆盖；提交时通过现有 `ConfirmActionDialog` 明确显示来源、目标、目录及覆盖策略。跨服务器目录逐文件应用策略，本地上传/下载沿用原有任务行为，默认跳过已存在的顶层条目。
4. 任务统一进入现有传输中心；独立标签显示全部任务，两端原会话都能看到相关复制任务。完成事件刷新当前双栏列表。
5. 原文件面板同时支持 A 标签复制、B 标签粘贴，默认跳过同名项；跨服务器剪切保持禁用，绝不在排队成功时删除来源。

表单、确认、上下文菜单、按钮、滚动条、虚拟文件表格及多选算法均复用现有公共实现；增加深浅主题与窄窗口布局回归。

## 数据路径与恢复

采用 `服务器 A → Rust 有界数据管道 → 服务器 B`，不把文件内容送入 renderer，也不先完整下载到本机磁盘。两端无需互相连通，只需本机可以访问两端。吞吐受本机网络和两端较慢一侧限制。

- 在各协议内部扩展现有独立传输通道的流式读写能力，保留 FTP/SFTP controller 分离。使用有界缓冲与背压，目标阻塞时停止继续读取来源，内存不随文件大小增长。
- 不用 `read_remote_file` 等全文读取接口搬运大文件，不在每个数据块重新建立连接；不占用目录浏览通道。
- 复用 transfer service 的任务状态、取消令牌、进度节流、防睡租约、journal、manifest 与目标替换逻辑。新增复制方向的执行分支，不伪装成互不关联的下载/上传任务。
- 目标写入任务拥有的唯一临时文件；完成流式 hash、目标验证和源身份复核后，才执行受保护的最终替换。当前统一通过两端文件通道回读 SHA-256 校验，兼容缺少服务端 hash 命令的 FTP/SFTP；该策略会增加校验读取流量，不把“长度相同”标成内容校验成功。
- 暂停、断线、应用重启保留目标断点；继续前重绑定两端连接并校验源身份、源前缀与目标临时文件前缀。无法证明连续前缀时拒绝直接追加，提供显式从头重传。
- 任一端断开都停止两端 IO，等待任务收口后再切换状态；丢弃只删除该任务拥有的临时数据，不删除源文件或原有正式目标。
- 目录遍历拒绝越界相对路径，首版发现符号链接时停止并报告具体路径；拒绝同一服务器的相同路径、自身子目录和可识别别名造成的递归复制。无法确认目录身份时拒绝危险目录复制。
- 源文件大小/修改时间变化时停止提交；同大小、同时间的原地改写仍不具备原子快照保证，需要用户保证复制期间源数据稳定。

| Rust commands、`lib/runtime.rs`、`src/bridge/tauri-api.ts` | 新建任务命令、注册与类型化桥接；Rust 校验会话能力、路径与授权范围                                                |

| `features/transfers/`                                      | 复制方向、双端名称、阶段、恢复条件与错误展示；排查所有方向二分判断                                               |
| fixtures、preview、测试、文档                              | 补齐复制任务样例、旧 journal 兼容、协议组合与失败恢复；实现完成后更新架构并归档计划                              |

MCP/CLI 首版不新增跨服务器 API，现有单会话 `copy_remote_path` 保持原语义。跨端元数据通过可选 `copySource` 与旧 upload/download 模型兼容；含复制任务时写入 journal v2，读取兼容 v1，阻止旧版误恢复新方向。无复制任务时继续写 v1。实现前检索所有 TransferTask 构造、direction 判断和 journal fixture；源文件超过项目行数门槛时按职责拆分，不机械扩充大文件。

## 实施顺序与验收

1. **双端任务与单文件链路**：先完成 SFTP → SFTP 的创建、复制、暂停、恢复、丢弃、重启 journal 兼容；以真实字节内容和故障恢复验证状态设计。
2. **FTP/FTPS 与目录**：完成协议组合、递归 manifest、空目录、符号链接提示、目标冲突与校验；对 FTP 不支持 REST/APPE 的情况提供安全重传。
3. **用户入口**：接入目标选择弹窗、任务中心和本地化；完成两端断线、目标只读、空间不足、重复点击、目标变化、关闭窗口与退出应用回归。

每步交付可验证结果，完整首版达到以上范围后再标记功能实现。关键自动化覆盖：有界背压、大文件、零字节、Unicode/空格路径、取消收口、前缀不匹配、源中途改变、目标提交失败、双端重连与旧 journal。协议夹具覆盖 SFTP/FTP/FTPS 双向及混合组合，真实服务器补做 FTPS 证书和网络中断验收。

代码实现按 AGENTS.md 运行 typecheck、lint、Prettier、renderer 测试、Tauri 测试、Clippy；UI 额外运行 CSS contract，并按开发版识别规则验收。实现和本机验证结果见 [跨服务器传输回归](../../quality/remote-to-remote-transfer.md)；未验证平台与真实部署环境单独列出，不代表用户反馈已解决或 Issue 可关闭。
