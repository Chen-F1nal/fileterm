# UI 图标资源归档

目标：将组件中的静态 SVG 图形原样移到 `renderer/assets/icons/`，保持现有路径、坐标、颜色继承、描边、大小和调用 API，不使用同名素材替换现有造型。

- [x] 提取 AppIcon 的 57 个名称；brand/terminal 共享资源；新增 3 个原窗口控件资源。
- [x] 文件拖拽预览复用资源，移除代码中重复的文件图标路径。
- [x] 从原 Material Symbols Outlined 400 静态字体提取 58 个实际使用字形，替换 87 处字体图标调用；移除 7 个不再使用的图标字体文件，保留 Apache 2.0 许可与来源记录。
- [x] 保持原有 63 个 SVG 素材不变；新增 117 个原样提取的资源，目录合计 180 个 SVG。
- [x] 原 AppIcon 的 57 名称 × 7 组描边，共 399 组几何摘要完全一致；Chromium 深浅主题同位置截图的 399 组像素差异均为 0。58 个 Material 字形的路径摘要及字体基线一致。
- [x] 类型、Lint、格式、238 项 Renderer 测试、Rust/contract 测试、Clippy、生产构建、字体/许可打包检查与 CSS contract 均通过。CSS 检查仍有 11 处历史 !important 和约 6 处旧颜色债务，没有新增。

所有应用自身的静态图标均从 assets/icons 读取。动态图表由数据生成，不属于静态图标；操作系统应用身份资产和 Monaco 内部 Codicons 保持各自平台及第三方边界。

## 外观与未验证项

- AppIcon 源文件由 408 行缩为约 30 行，图形数据进入独立 SVG，注册表和描边参数处理各自独立；没有超过 1000 行的被修改业务源文件。
- Material 字体转 SVG 的轮廓、原 400 字重和基线保持一致，但字体与 SVG 的边缘抗锯齿渲染存在差异，不能宣称这部分逐像素一致；没有额外加粗、移动或换成同名图库素材。
- Chromium 已生成原字体与提取 SVG 的 18px/24px 并排对比。WebKit 测试引擎本机未安装；macOS、Windows、Linux 原生窗口视觉检查尚未执行。
- 手动验收发现带背景框和内边距的图标尺寸回归：SVG 应按原 `font-size` 的 1em 显示，不应填满外框；外层默认尺寸恢复内容自适应。Chromium 已断言 AI 标题、空对话、Provider 和管理工具的图形尺寸分别为 16、19、18、20px，外框分别为 28、38、32、36px。
- 扩展复查全部 87 处原字体图标调用点：使用源码祖先结构与实际 CSS 构造对照场景，覆盖侧栏收起状态、四个内置主题和 320/900px 容器，共 752 组；迁移前后外框尺寸、父容器内位置、字号、颜色、内边距、display 和静态 transform 无差异。动画在测量期间冻结；此检查不替代原生完整页面验收。原 AppIcon 399 组深浅背景像素对照复跑仍为零差异，未发现需要额外修改的样式。
