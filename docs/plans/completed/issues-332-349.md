# Issues #332 / #349

Refs #332, Refs #349.

## Scope

- #332: extend the existing Show Whitespace preference with visible LF (`↓`)
  and CRLF (`↵`) markers. Keep markers out of the document, clipboard and saved
  text; refresh them after edits, EOL conversion, undo and viewport changes.
- #349: let both the file icon and name start the existing internal pointer
  transfer. Keep other columns available for drag selection, retain multi-file
  transfers, and reject same-pane, cancelled and disconnected drops.
- Reuse upload/download callbacks and existing conflict handling. No new IPC,
  dependencies, native drag-out support or transfer implementation.
- When CI surfaced newly published critical certificate-chain/root-certificate
  advisories, update only the affected Cargo.lock entries to patched releases:
  `rustls-webpki` 0.103.16 and `webpki-roots` / `webpki-root-certs` 1.0.10.

## Changes

- `file-editor-line-endings.ts` owns viewport-only Monaco injected text and its
  listeners; the existing editor mount installs it. Its CSS consumes `--text-muted`.
- `FileNameCell` owns the pointer gesture across icon and name. Drag cursor rules
  move from the legacy session stylesheet into the file-table stylesheet.
- Starting a new name/icon gesture clears a previous drag's suppressed click.
- Extend the real Monaco and file-manager browser fixtures. The directory-tree
  fixture also needs the current controlled pane-mode props; the original fixture
  times out when switching modes without them.

## Validation

- Passed: `npm run typecheck`, `npm run lint`, repository Prettier gate,
  `npm run test:renderer -w @fileterm/tauri` (155 tests), `npm run test:tauri`,
  locked all-target/all-feature Clippy, CSS contract and `git diff --check`.
- Passed with bundled Playwright and installed Chrome:
  `node apps/tauri/tests/browser/file-editor.mjs` and
  `node apps/tauri/tests/browser/remote-directory-tree.mjs --drag-only`.
  File dragging covers name/icon upload, name download, selected files,
  same-pane no-op, cancellation and disconnected rejection in all three
  renderer platform branches. Editor checks cover marker toggling/persistence,
  LF/CRLF conversion/undo/save, no marker on the final unterminated line, and
  viewport-only markers after scrolling. Inspected dark/light screenshots.
- Full directory-tree browser scenario remains blocked by an unrelated theme
  preview divider assertion (`rgba(0, 0, 0, 0)` versus `rgb(48, 48, 48)`).
  Its unmodified baseline first fails earlier on the missing controlled props.
- CSS contract reports existing non-blocking debt (11 `!important` occurrences
  and approximately 6 legacy direct colors). Editor viewport resizing also
  produced Vite ResizeObserver notifications; browser assertions passed.
- After the Cargo.lock security updates, local `cargo audit` passes with the
  same six existing ignored IDs as CI; the prior 3 certificate advisories no
  longer appear. Cargo test and strict Clippy are rerunning for the lock update.

## Limits

- Monaco normalizes standalone CR and mixed line endings when loading a model.
  Markers describe the current editable model's LF/CRLF, not the original bytes.
- Browser platform branches do not replace native macOS 27, Windows or Linux
  transfer verification against an actual remote server.
- Keep both Issues open pending release and user verification.
