# 持续写入文件的流式上传校验

## 问题与目标

上传后重新读取本地源文件计算 SHA-256，会把持续追加日志误判为传输失败；读取至 EOF 也会超过任务记录的大小。使用固定内存缓冲计算本次上传的 hash，不创建本地临时副本。

## 实现范围

- transfer service 将本次任务记录的源大小传入上传 worker，单文件和目录条目共用边界。
- SSH/SFTP、root exec 和 FTP/FTPS 按固定长度读取并计算 SHA-256；校验阶段使用流式结果，下载保留原有行为。
- 续传先读取本地已有前缀计算 hash，再发送后缀。SFTP/FTP 在写入前读取远端断点并核对完整前缀，拒绝内容或长度不匹配的断点，服务器无需支持 hash 命令。
- 旧 root exec 回退路径恢复时必须取得远端完整 SHA-256，否则失败并保留断点，不提交正式目标。常规 root staging 使用 SFTP 前缀检查。
- FTP 的 APPE → REST/STOR → 从零重建保留现有策略，每次重建重新初始化 hash。

## 验证

- 共享读取器：追加、截断、空文件、非法 offset、完整断点、前缀不匹配、取消和超时。
- 本机 FTP 协议夹具：APPE、REST/STOR、不遵守 REST 的从零回退、等长错误前缀，以及上传后源文件变化仍能正确校验。
- 完成类型、lint、Prettier、renderer、Rust/contract 与 Clippy 门禁。

## 边界

- 固定上传长度不等于文件系统原子快照。持续追加不影响本次上传；读取期间原地改写可能产生跨时刻内容。
- 续传需要读取本地与远端已有前缀，会增加读取与网络流量；无法读取断点时拒绝续传。
- 原有源身份变更检查保留；暂停后源文件变化仍需重新传输，不自动复用旧断点。

## 完成结果（2026-10-24）

- 已移除本地临时副本草稿，生产上传不增加临时磁盘占用。
- 已取消“完整大小断点直接提交”的跳过路径；完整断点也必须核对内容。SFTP/FTP 核对成功后不再重写完整断点。
- 类型、lint、Prettier、renderer 200 项、Rust 单元测试 864 项、CLI 10 项、contract 23 项及 Clippy（locked/all-targets/all-features、warnings 作为错误）全部通过。
- 真实 OpenSSH/SFTP 夹具验证了固定长度上传、部分/完整断点和错误前缀保护；FTP 夹具验证了 APPE、REST/STOR、忽略 REST 后的从零重建与 hash 重置、完整断点和上传后源文件改写。
- 未进行 Windows/Linux 实机或桌面 UI 手工验证；旧 root exec 回退的 sudo/su 实机上传未另行验证。

## 复查加固

- FTP/FTPS 登录后显式启用二进制模式；协议夹具要求先收到 `TYPE I`，新传和续传均验证 CRLF 字节及其 hash。
- 断点核对失败立即返回原始错误，不等待 RETR 完成响应；夹具故意省略错误断点的 `226` 响应，确认错误不会被收尾超时覆盖。
- FTP 上传/下载的 ABOR 与独立连接 QUIT 均限制等待时间。SFTP 上传的 flush/CLOSE 确认统一纳入取消与超时，关闭时的错误会传回任务。
- Unix 打开上传源使用 `O_NOFOLLOW | O_NONBLOCK`，打开后再检查普通文件属性；回归测试覆盖符号链接和无写入端的 FIFO，避免扫描后路径被替换导致意外读取或卡住。
- 截断、断点内容不匹配及大小变化归为永久错误，目录任务不再为这些错误进行无意义的自动重试；增加核对期间取消的测试。
